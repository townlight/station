# ADR 0067: Reporting authority

## Decision

`station-reporting` owns a pure, fail-closed contract for a future authenticated
as-run projection input, exact UTC windows, deterministic hours by
franchise/category, EPG export configuration, X-List/XMLTV/CSV renderer input, and
immutable export receipts. It does not currently consume, read, mutate, or replace
the worker journal.

The current journal is not this projection input. Its records do not carry the
wall-clock interval, content identity, franchise, or category required here, and its
mixed/compacted sequences are not a contiguous reporting timeline. A future adapter
must derive UTC timing and enrich each fact, then authenticate a separate journal
evidence binding that names journal identity, source-record range/hash, worker
candidate, authenticator, time, and proof hash. This crate validates the canonical
evidence binding; it does not implement that adapter or authenticate its proof.

Each future fact has a versioned SHA-256 digest derived by a length-prefixed canonical
encoding of every factual field. Its separately authenticated journal binding names
that exact fact digest. A projection names one channel, revision, exact UTC half-open
window, and ordered fact digests. Its projection sequence and time must be contiguous
from exact window start through end; gaps, duplicates, overlaps, channel mismatch,
altered fields/digests, and substituted journal evidence fail closed. Projection
sequence is deliberately separate from the current journal's mixed record sequence.
Hours are derived deterministically by ordered franchise/category key; caller totals
are rederived and compared.

X-List, XMLTV, and CSV contracts carry typed rows that exactly reproduce source facts
and a versioned canonical export digest. Titles are intentionally absent until a
future slice can bind exact catalog/content-metadata revision and digest. EPG and
receipt text is bounded and rejects controls, markup, CSV separators, backslashes,
and spreadsheet-formula prefixes. EPG configuration has revision-one creation and
CAS replacement; its identity/channel cannot be rebound. Export receipts are
append-only, one-per-export, and must bind the exact validated export digest, report,
projection revision, and source fact digests. Receipt outcomes describe only future
rendering acceptance or rejection—not generated bytes or delivery.

## Boundaries and non-claims

### Runtime adapter foundation

`station-reporting::runtime` now provides a bounded, replay-safe projection
foundation for an already authenticated, catalog- and schedule-enriched journal
take. It rejects channel rebinding, malformed hashes, invalid intervals, sequence
gaps, overlaps, and unbounded input. A discontinuity must be represented by an
explicit `gap` state; fallback, live, CG, and caption states remain visible with an
explicit unavailable reason instead of being transformed into program-airing facts.
The checkpoint is deterministic and cannot move backwards, so a caller can replay a
journal after a crash without changing accepted output. CSV and XMLTV bytes are
deterministic, UTC-labelled, and XML/CSV escaped; the station timezone is retained
as presentation metadata and never changes the authoritative UTC interval.

This is deliberately a foundation, not proof that the existing worker journal can
produce enriched takes. The persistent SQLite adapter, catalog/schedule join,
authenticated API/RBAC boundary, operator page, and delivery workflow remain
required before S23 can be claimed as operational.

`station-storage` now owns the corresponding backward-compatible SQLite schema:
one current bounded projection/checkpoint row per channel and immutable,
append-only per-event projection evidence. Projection persistence uses the existing
single writer with `BEGIN IMMEDIATE`; identical replay is idempotent, conflicting
reuse of an immutable event identity fails closed, and a persisted checkpoint cannot
move backwards. Reopening the database reads and validates the saved projection.
This persistence boundary accepts only a trusted in-process projection; it is not an
HTTP ingestion route and therefore does not let a browser assert aired facts.

The trusted journal adapter reads CRC-checked durable `ScheduledAssetOnAir`
records. A CRC detects accidental corruption; it is not an authenticator. Its
projection hash covers the complete canonical protocol frame plus configured journal
identity (derived from the durable worker identity, not a caller assertion), making channel, worker boot, report, media-offset, protocol, and event
field changes visible in immutable stored evidence. Local journal ownership remains
the trust boundary.

The current event does not carry an immutable catalog revision/snapshot. The adapter
therefore never substitutes a mutable current schedule or catalog row during replay:
title, franchise, category, catalog revision, and schedule revision are `None` with
a bounded unavailable reason. The journal asset identity is retained as a
journal-derived binding, not a catalog claim. It projects only intervals closed by
the next durable timed event; no synthetic trailing gap is created, so later journal
growth can replay without conflicting with persisted evidence. Live, CG, caption,
and fallback events lack a durable timing fact and cannot establish an airing
interval. This is truthful incompleteness, not delivery or field proof.

Authenticated enabled Setup Admin and Meeting Operator accounts may read bounded
pages of an already persisted projection or request bounded CSV/XMLTV bytes. The
API has no projection-write or fact-ingestion route. Every successful read/export
appends a server-attributed immutable access-audit row only after the bounded page
or bytes are constructed; invalid query shapes, unavailable projection, render
failure, and audit failure fail closed without a success audit.

The operator Reports screen is a read-only view of that authority. It validates the
complete response shape, bounded fields, ordered entries, source/checkpoint binding,
and opaque continuation pages before presenting them. It refuses to combine pages
whose channel, window, journal/file source, raw sequence, or checkpoint revision
changes, and it does not accept projection facts from the browser. CSV and XMLTV
links use the authenticated server export routes. The screen labels absent metadata
and journal gaps explicitly and states that neither the projection nor an export
proves receiver delivery, downstream publication, playback, or audience viewing.

This crate has no journal adapter, UTC timing derivation, content/franchise/category
enrichment, evidence authenticator, worker-journal reader/writer, persistence, API,
UI, catalog metadata join, EPG feed renderer, filesystem/network export delivery,
scheduler, timezone conversion runtime, or installed/field proof. It does not
establish that future projection facts are truthful, that current journal records can
produce them, that a report/export was rendered or delivered, that a receiver
consumed it, or that an EPG listing was published. Later slices must build and prove
the authenticated adapter, bind exact catalog metadata when titles are introduced,
persist authority through the single SQLite writer, render/deliver exports, and
acquire installed-machine and field evidence.
