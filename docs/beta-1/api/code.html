API reference scope

This is the Townlight Beta 1 technical contract for Code. The desktop-domain entries below come from the installed candidate’s generated OpenAPI schema. Export did not start a server, enter application lifespan, run migrations or contact a database. It is schema evidence, not proof of every endpoint’s runtime behavior. The acceptance section of the operating manual identifies exercised paths.

The complete filtered OpenAPI JSON preserves request bodies, parameters, response declarations, constraints and referenced schemas. An empty response schema means that this application did not declare a structured response model; do not infer a stronger contract from a green HTTP status. HTTP authorization enforced inside dependencies is still required when an automatically generated header parameter says optional.

Origins and authentication

The canonical native domain transport uses http://127.0.0.1:15480. The native shell supplies X-Townlight-Session and maps it to a persisted SQL identity; browser code must not invent an actor or role. A trusted local integration must protect that proof as a credential and revalidate current authority. Standalone /auth/jwt/login uses the existing bearer-token flow; that token is not interchangeable with native proof. Public routes have their own permission and deployment gates. Do not bind the native domain runtime to a non-loopback interface.

Station defaults to explicit loopback port 8756. Its service revalidates Townlight authority. Its browser exchanges a one-use 60-second ticket for a 900-second HttpOnly SameSite Strict operator cookie. Browser mutations require the exact Origin and X-Station-UI: 1. Native session proof must not be put in a URL or shipped to an MCP client.

Failure and retry contract

401 means missing/expired identity; 403 means permission or origin denial; 404 means a missing or unavailable resource; 409 commonly means revision, source-hash, lifecycle or idempotency conflict; 422 means invalid input; 429 means a bounded rate/capacity refusal; 503 means an unavailable dependency, configuration or schema. Individual routes may use only a subset and source-derived checks can add errors absent from generated response declarations. Preserve edits, read the detail and inspect current state before retrying a write. Neither a retry nor an idempotency key authorizes a changed payload.

Effective installed runtime contract

The inner domain export in reference/desktop-domain-openapi.json has 243 paths and 245 schemas. The installed host is a second FastAPI application: it registers GET /health, GET /modules and GET /ready before mounting that domain application at /. Its /health therefore overrides the inner app.main.health at the installed origin. The effective composition has 245 unique URI paths. The filtered downloads for Suite, Core and Records compose those real outer routes over their inner-domain selection; the original inner and outer exports remain separate evidence files.

Outer operation Actual response and use
GET /health Runtime status (ok or degraded), service/version, product profile, module checks, database check and local_only. HTTP 200 when healthy, otherwise 503. This is not the inner app’s simple status/version handler.
GET /modules The same runtime health payload and HTTP status as /health; not a second independent readiness proof.
GET /ready status (ready or not-ready) and reason; HTTP 200/503 after the applicable activation, schema and provider checks. Use this for domain readiness.

For example, a ready result has shape {"status":"ready","reason":"<actual profile-specific readiness reason>"}; an inactive domain returns {"status":"not-ready","reason":"domain-inactive"} with 503. These are source-derived shapes, not new execution receipts. Read the actual reason rather than treating a listening process or /health alone as canonical readiness.

The native origin remains http://127.0.0.1:15480. Station’s separately paired suite process can use another explicitly configured loopback port; its Station origin and the Station service’s suite origin must agree. The Station operating guide supplies that setup without disabling normal activation.
